URL to PDF API: turning web pages into permanent files

November 21, 2026

Some web pages matter long after their URL stops working. A receipt from a payment portal, a contract page from a vendor, a dashboard you need to attach to a report — all of them live online until the moment they don't. A URL to PDF API turns any public page into a file you own.

What you're actually paying for

Pointing headless Chromium at a URL is easy. Pointing it at untrusted URLs is where self-hosting gets expensive:

  • SSRF. A URL renderer is a machine that fetches whatever you tell it to fetch. If you render user-supplied links, someone will try your internal network. A proper renderer resolves DNS first, refuses private and loopback addresses, and verifies that the connection target matches the DNS answer — because DNS rebinding is a thing.
  • Waiting for the right moment. Most pages render twice: a skeleton, then the real content. Capturing too early gives you a half-empty page. A good renderer waits for the network to settle before the shutter clicks.
  • Print styles. Screens scroll; paper paginates. Without a print stylesheet the PDF comes out as one long, awkward column with no page numbers.

PDF or PNG?

For archiving and distribution, PDF wins: fixed A4 pages, printable, page numbers in the footer. For a visual in a report or a thumbnail in an app, PNG is the better call — it renders at a set viewport and captures the full page height.

curl -X POST https://api.renderdock.dev/v1/render \
  -H "Authorization: Bearer rd_your_api_key" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://example.com/receipt", "format": "pdf"}' \
  -o receipt.pdf

Where this fits

Most teams build this once: an order confirmation page that becomes a PDF for the customer, a weekly digest of competitor pages, an archive of a vendor portal. Each one is one request.
